# Витрины данных Казначейства (datamarts)

| Признак | Значение |
| :--- | :--- |
| Уровень и охват | Федеральные аналитические отчёты Казначейства: доходы, расходы, результат исполнения, финансовые результаты, консолидированный бюджет, учреждения и справочные показатели |
| Тип доступа | HTML-оболочка WordPress, JSON-запросы движка Krista и серверный экспорт активного отчёта в XLSX |
| Основные форматы | HTML, JSON, XLSX; на 19.07.2026 CSV, XML и отдельный публичный файловый каталог на этом хосте не подтверждены |
| Оператор | Федеральное казначейство |
| Режим доступа | Открытый: проверенные страницы, JSON и XLSX работают без учётной записи |

Коротко: это не каталог заранее размещённых файлов, а набор интерактивных отчётов. Для воспроизводимого анализа можно обращаться к наблюдаемому JSON-интерфейсу отчётов или запрашивать XLSX-экспорт; в обоих случаях нужно зафиксировать `uuid`, `dataVersion`, `dsCode`, период и масштаб денежных сумм.

## Описание

Главное меню фактически содержит разделы «Доходы», «Расходы», «Результат исполнения», «Финансовые результаты деятельности», «Макроэкономические показатели», «Консолидированный бюджет РФ и ГВБФ», «Консолидированные данные по ППО и учреждениям», «Бюджетные и автономные учреждения», «Справочные данные» и инфографику. На 19.07.2026 в меню **нет** витрины «Закупки».

Каждая страница отчёта загружает JavaScript-движок Krista. В HTML видны идентификатор отчёта и его версия; затем браузер получает модель отчёта и массивы значений из `/reporting/Data`. Кнопка экспорта отправляет `POST` на `/reporting/print` и получает заново сформированный XLSX. Поэтому постоянной прямой ссылки на один файл здесь нет: устойчивым идентификатором служит сочетание идентификатора отчёта, версии, кода набора и параметров.

Страница [«Открытые данные»](http://datamarts.roskazna.ru/otkrytye_dannye/) существует в дереве WordPress, но при проверке не содержала карточек наборов или файлов. Путь `https://datamarts.roskazna.ru/opendata/` возвращал страницу 404 WordPress. В этой карточке не предполагается, что на datamarts есть каталог `/opendata/`, CSV-файлы либо метаданные лицензии, версии файла и периодичности по наборам.

Сюда не входят внутренние казначейские кабинеты, первичные записи платежей, построчные контракты ЕИС и наборы другого хоста `budget.gov.ru`.

### Доходы: основные виды — структура

Это иерархия укрупнённых видов доходов федерального бюджета. В JSON массив каждой строки необходимо сопоставлять со схемой ниже: сервер не возвращает объект с именами полей.

| Колонка | Тип | Описание | Ключ связи / справочник | Пример значения в JSON |
| --- | --- | --- | --- | --- |
| `commentEmptyColumn` | string | Техническая колонка для индикатора комментария. | Не ключ. | `""` |
| `name` | string | Наименование агрегата доходов. | Текстовая подпись, не стабильный код; не джойнить как КБК. | `"ВСЕГО ДОХОДОВ"` |
| `plan` | float | Уточнённый прогноз доходов. | Сопоставим только после фиксации периода и масштаба; для классификации см. **[КБК](/glossary/kbk)**, которого в этом ответе нет. | `26130.286112` |
| `fact` | float | Кассовое исполнение. | Связь по периоду и методике с **[казначейским исполнением](/glossary/treasury-execution)**, не построчный ключ. | `29124.0499144916` |
| `deviation` | float | `fact` минус `plan` в выбранном масштабе. | Производный показатель. | `2993.7638024916` |
| `forecastPercent` | float | Отношение исполнения к уточнённому прогнозу; в JSON дробь, в XLSX процент. | Производный показатель. | `1.1145706476255100` |
| `share` | float | Доля в общем объёме доходов; в JSON дробь. | Производный показатель. | `1.00` |
| `growth` | float | Прирост/сокращение к предыдущему году; в JSON дробь. | Сопоставляйте с `prevYear`. | `0.0467092670768983` |
| `prevYear` | float | Год для сравнения. | Временной ключ, но не отчётный период строки. | `2022.0` |
| `level` | float | Уровень иерархии строки. | Используйте с порядком строк для группировки, не как идентификатор. | `1.0` |
| `text` | string | Пояснение/ссылка на закон, использованный для плана. | Не нормированный идентификатор НПА. | `"(в соответствии с Федеральным законом от 05.12.2022 № 466-ФЗ)"` |
| `comment` | string | Текст комментария к строке. | Не ключ; в проверенных строках `null`. | `null` |

У представления «Динамика» отдельная схема: `name` (string), `year1`–`year17` (float) и `level` (int). В модели отчёта эти поля подписаны как 2007–2023 соответственно; в проверенной первой строке `year17` равен `29124.0499144916`. Не выводите год из порядкового номера без проверки модели: подписи столбцов являются частью конкретной версии отчёта.

| Колонка | Тип | Описание | Ключ связи / справочник | Пример значения в JSON |

| `fact` | float | Исполнено. | Агрегат кассового исполнения; не ссылка на одну строку формы 0503…. | `1252.25269413811` |

В проверенном ответе 46 строк; `imgId` — технический идентификатор иконки, а `parent` — связь для отрисовки, не код госпрограммы.

### Форматы и соглашения парсинга

- **CSV.** На проверенной площадке CSV не найден: нет разделителя, BOM или кодировки CSV, которые можно было бы честно зафиксировать.
- **JSON.** Ответы имеют `Content-Type: application/json`; данные лежат в `data` как массивы массивов и числовые показатели передаются с десятичной точкой. Кириллица в полезной нагрузке читается как UTF-8, но сервер не добавляет `charset` в заголовок. Имена колонок берутся из модели отчёта, а не из ответа данных.
- **XLSX.** Экспорт — OOXML. Первый лист у трёх проверенных файлов называется `mytable4`. Денежные и процентные значения в листе экспортированы как форматированный текст: неразрывный пробел как разделитель разрядов, десятичная запятая и знак `%` (`29 124,05`, `111,5%`). Перед расчётами преобразуйте их явно.
- **Даты и период.** Список доступных периодов у трёх отчётов вернул одно значение `2023-01-01T00:00:00.000Z`; в метаданных внешнего источника указан формат `DD.MM.YYYY`. В проверенных XLSX период обозначен текстом `Год : 2023`, а не отдельной колонкой даты.
- **Масштаб денег.** В запросе `paramRubMultiple=1000000000` листы подписаны `млрд. руб.`; модель допускает также `1000000` для `млн. руб.`. Примеры чисел в таблицах этой карточки получены при масштабе миллиардов — это не рубли.
- **Служебные строки.** В XLSX «Доходы» и «Госпрограммы» строки 1–4 — название, подзаголовок, год и единицы; заголовок на строке 5, данные с 6. В «Расходах» строки 5–7 — трёхуровневая объединённая шапка, данные с 8; пустую итоговую/служебную строку следует отбросить.

### Ключи связки и пробелы

В трёх проверенных таблицах **нет** КБК, ОКТМО, кода субъекта, ИНН, ЕИНН и реестрового номера контракта. В частности:

- `code` в расходах — только РзПр; он не заменяет **[КБК](/glossary/kbk)** и не даёт связать витрину с детализацией по виду расходов без дополнительного классификатора.
- Доходы и госпрограммы публикуют названия и уровни иерархии, но не устойчивые машинные идентификаторы. Джойн по `name` возможен только как вручную проверяемое эвристическое сопоставление.
- Для контрактного уровня и реестрового номера используйте **[XML-выгрузки ЕИС](/data-sources/federal/zakupki-xml)**: на datamarts нет подтверждённой витрины закупок.
- Для строк по КБК и форм исполнения сопоставляйте период, единицу и методику с **[наборами ГИИС «Электронный бюджет»](/data-sources/federal/budget-gov-ru-datasets)** и **[отчётами Казначейства](/data-sources/federal/roskazna-reports)**. Значения не обязаны совпадать построчно из-за разного среза и агрегации.

## Периодичность обновления

Периодичность не опубликована. Метаданные внешнего источника `DataMartStelsXML` вернули `updateRate: 0`, `lastPeriod: 2023-01-01T00:00:00.000Z` и `dateModified: 2025-01-21T14:13:41.175Z`; из этих полей нельзя вывести регулярную частоту или лаг относительно кассового факта. Перед каждым регулярным запуском сначала запрашивайте `ds_DataMartStelsXML_Periods` и сохраняйте ответ вместе с результатом.

## Ограничения и особенности

- HTTPS на дату проверки имеет сертификат с несовпадающим именем хоста. Обычный `curl https://…` завершался ошибкой TLS; не используйте `-k` в производственном конвейере.
- JSON-интерфейс наблюдается в коде публичной страницы, но не опубликован как стабильный API. `uuid`, `dataVersion`, `dsCode`, поля и маршруты могут измениться без версии API.
- Заголовок `Range: bytes=0-99` на проверенном `POST /reporting/print` был проигнорирован: сервер ответил `200 OK` полным XLSX размером 16 149 байт, без `Accept-Ranges`. Возобновляемую частичную загрузку не предполагаем.
- Проверенные API- и экспорт-запросы работали с обычным `curl` и с заданным generic `User-Agent`; обязательность `User-Agent` сервер не заявил. В примерах он указан для прозрачности журналов, а не как обход ограничения.
- Версия моделей датирована 2015–2016 годами, хотя доступная страница и метаданные менялись позже. Это не доказательство актуальности показателей после 2023 года.

## Примеры доступа

Ниже команды выполнены 19.07.2026 для витрины «Доходы: основные виды». Они используют HTTP по причине описанной выше проверки TLS.

### Скачать сформированный XLSX

```bash
curl --fail --silent --show-error \
  -A 'Mozilla/5.0 (compatible; finguide-research/1.0)' \
  -X POST 'http://datamarts.roskazna.ru/reporting/print' \
  --data-urlencode 'reportId=299b92f0-4cc1-4a45-aaa1-398ce3e62d25' \
  --data-urlencode 'version=24.06.2015 10.26.05.000' \
  --data-urlencode 'format=xlsx' \
  --data-urlencode 'state={"controls":{},"filters":{},"paging":{},"systemParameters":{}}' \
  --data-urlencode 'parameters=[{"name":"paramRubMultiple","value":"1000000000"},{"name":"paramPeriod","value":"2023-01-01T00:00:00.000Z"},{"name":"viewCode","value":"Struct"}]' \
  --output income-2023.xlsx
```

Ответ имеет `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`. Это создание нового файла сервером, а не скачивание файла с постоянным URL; исходной текстовой кодировки у XLSX нет.

### Прочитать проверенный XLSX в pandas

```python
import pandas as pd


def ru_number(series: pd.Series) -> pd.Series:
    """Преобразует текст XLSX вида «29 124,05» и «111,5%»."""
    return pd.to_numeric(
        series.astype("string")
        .str.replace("\u00a0", "", regex=False)
        .str.replace(" ", "", regex=False)
        .str.replace("%", "", regex=False)
        .str.replace(",", ".", regex=False),
        errors="coerce",
    )


# В реальном файле: 1–4 — служебные строки, строка 5 — заголовок.
frame = pd.read_excel(
    "income-2023.xlsx", sheet_name="mytable4", header=4,
    dtype=str, engine="openpyxl",
)
frame = frame.drop(columns=frame.columns[0]).dropna(how="all")

assert frame.columns[0] == "Вид доходов"
# Следующие три реальные колонки: прогноз, кассовое исполнение, отклонение.
value_columns = frame.columns[1:4]
# Далее идут: % исполнения, доля, прирост/сокращение.
percent_columns = frame.columns[4:7]
frame[value_columns] = frame[value_columns].apply(ru_number)
frame[percent_columns] = frame[percent_columns].apply(ru_number) / 100
```

Для файла расходов с объединённой трёхстрочной шапкой используйте не `header=4`, а явные имена после пропуска семи строк:

```python
expenses = pd.read_excel(

    skiprows=7, usecols="A:J", dtype=str, engine="openpyxl",
)
expenses.columns = [

    "cash_execution", "to_law_amount", "to_law_pct",
    "to_schedule_amount", "to_schedule_pct", "share_pct",
]
expenses = expenses.dropna(how="all")
```

## Связанные страницы wiki

- **[Портал Федерального казначейства](/information-systems/federal/roskazna-portal)** — оператор и общий контекст публичных сервисов Казначейства.

- **[Казначейское исполнение бюджета](/glossary/treasury-execution)** — объясняет смысл кассового факта, который витрины показывают агрегированно.

## Не путать с

- **[Отчёты Федерального казначейства](/data-sources/federal/roskazna-reports)** — файловые регламентированные формы и публикации; datamarts — интерактивные агрегаты и генерируемый экспорт.
- **[Наборы данных ГИИС «Электронный бюджет»](/data-sources/federal/budget-gov-ru-datasets)** — другой хост и другой каталог наборов; совпадение темы или периода не означает совпадения схемы и методики.
- **[XML-выгрузки ЕИС Закупки](/data-sources/federal/zakupki-xml)** — полный файловый след закупочных документов, а не отсутствующая на datamarts витрина «Закупки».

## История и контекст

Страницы отчётов используют версии моделей 2015–2016 годов, однако в меню есть периоды 2020–2023, а основные разделы WordPress изменялись в 2025 году. Наблюдаемая модель ближе к legacy-отчётному порталу: браузер получает HTML-оболочку, а данные — от отдельного Krista-сервиса. Это объясняет, почему год в имени создаваемого XLSX — дата экспорта, а не идентификатор опубликованной версии файла.

## Частые вопросы

**В:** Можно ли регулярно скачивать один постоянный XLSX URL?

**О:** Нет. Проверенный механизм — `POST /reporting/print` с идентификатором отчёта, его версией, активным представлением и параметрами. Он создаёт новый файл на момент запроса; фиксируйте эти параметры и контрольную сумму полученного файла.

**В:** Почему в JSON `forecastPercent` равен `1.114…`, а в XLSX показано `111,5%`?

**О:** В ответе JSON для этой витрины доли передаются дробью, а экспорт форматирует их как проценты. В таблице госпрограмм поле `percent`, напротив, уже приходит как число процентов (`98.83`). Масштаб и соглашение нужно брать из схемы конкретного `dsCode`.

**В:** Есть ли в datamarts данные по отдельным контрактам или КБК?

**О:** В трёх проверенных главных таблицах таких ключей нет. Для контрактов переходите к **[XML-выгрузкам ЕИС](/data-sources/federal/zakupki-xml)**, а для классификационной детализации — к источникам, которые действительно публикуют **[КБК](/glossary/kbk)**.
