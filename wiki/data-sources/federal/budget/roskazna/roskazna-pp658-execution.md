# Казначейство: исполнение постановления Правительства РФ от 08.06.2018 № 658 (раздел портала)

| Признак | Значение |
| :--- | :--- |
| Уровень и охват | Методическая страница **для ФОИВ и их подведомственных учреждений** в ветке «Государственные информационные системы» портала Казначейства; датасетов не содержит |
| Тип доступа | Плоский HTML-список из 10 вложений без фильтров; API нет |
| Основные форматы | DOCX, PPTX, PDF; архивы ZIP (имена внутри CP866) и RAR; внутри одного ZIP — старые бинарные .doc |
| Оператор и публикатор | [Федеральное казначейство](/organizations/federal-treasury) |
| Режим доступа | Открытый; прямые адреса вложений не являются постоянными endpoint'ами |

Коротко: страница — **замороженный с апреля 2020 года комплект методических материалов**, которыми Казначейство сопровождало переход федеральных органов исполнительной власти на централизованное программное обеспечение бюджетного учёта, закупаемое по постановлению Правительства РФ от 08.06.2018 № 658. Для аналитика открытых данных здесь нет рядов показателей; практическая ценность — **альбомы ТФФ** (XML-форматы обмена ведомственных ИС с ГИИС «Электронный бюджет» по реестру начислений и доходам) и документация этапа централизации учёта 2019–2020 годов.

## Описание и границы

Карточка описывает страницу [«Исполнение ПП РФ от 08.06.2018 № 658»](https://roskazna.gov.ru/gis/ispolnenie-pp-rf-658/) в ветке `/gis/` портала Казначейства. Пункт меню находится в разделе **«Государственные информационные системы»** (вместе с ГИС «Электронных сертификатов», «Независимый регистратор» и сайтом bus.gov.ru), а **не** в «Исполнении бюджетов», как можно предположить по тематике.

Постановление Правительства РФ от 08.06.2018 № 658 «О централизованных закупках офисного программного обеспечения, программного обеспечения для ведения бюджетного учета и программного обеспечения в сфере информационной безопасности» — режим, при котором ПО для бюджетного учёта закупается централизованно (в контуре закупочного законодательства — см. [44-ФЗ](/legal/44fz)). Одновременно в 2019–2020 годах ФОИВ «первой» и «второй» очередей передавали Казначейству полномочия по ведению бюджетного учёта, формированию отчётности и начислению выплат (казначейские полномочия — [ст. 166.1 БК РФ](/legal/budget-code)). Страница — операционный след этого перехода: анкеты, форматы обмена, инструкции и презентации ВКС, прочитанные для второй очереди ФОИВ (переход с 01.01.2020).

Сюда **не** входит: исполнение федерального бюджета как таковое (см. [формы 0503117/0507011](/data-sources/federal/roskazna-federal-budget-execution)), данные о закупках ПО, реестры лицензий, сводные отчёты. Актуальные машиночитаемые наборы контура «Электронного бюджета» описаны в [карточке наборов данных](/data-sources/federal/budget-gov-ru-datasets).

## Оператор

- [ГИИС «Электронный бюджет»](/information-systems/federal/giis-eb) — система, с которой настраивается обмен по документации страницы.
- [Портал Федерального казначейства](/information-systems/federal/roskazna-portal) — витрина, на которой размещён раздел.

## Объекты данных и показатели

- **Датасетов на странице нет.** Объекты — документы; числовые ряды извлечь неоткуда.
- Единственная часть, близкая к данным, — **альбомы ТФФ**: описание XML-файлов обмена между ведомственными ИС и ГИИС «Электронный бюджет». Состав передаваемых данных: реестр начислений и поступлений по доходам федерального бюджета; поступление, выбытие и возврат средств во временном распоряжении.
- Электронный формат обмена — **XML в кодировке WINDOWS-1251**; пример имени файла выгрузки: `1234567890_123456789_20180605_01.xml` (пара ИНН-подобных идентификаторов системы-источника, дата `YYYYMMDD`, порядковый номер).
- Роли в регламенте обмена: «Администратор доходов» и «Бухгалтер»; альбом включает проверки при загрузке и тексты ошибок протокола.
- Ключи связки с другими наборами из документации не следуют; это спецификация интеграционного слоя, а не выгрузка.

**Пробелы**: нет сводок о том, сколько ФОИВ перешло, какие волны охвачены, какие ПО закуплено; нет архивов версии страницы; RAR-приложение к карте контроля требует проприетарного распаковщика.

## Структура файлов и словарь данных

### Карта контроля

Шаблон-анкета «для анализа технологического обеспечения ведения бюджетного учета, формирования бюджетной отчетности, начисления и выплаты заработной платы и иных выплат в бюджеты». Разделы опроса: общая информация об организации (наименование; **код в реестре участников бюджетного процесса**, пример заполнения `00100160`; количество территориальных органов; количество подведомственных казённых учреждений), ответственный за инфраструктуру и эксплуатацию прикладного ПО (ФИО, должность, телефон, e-mail), численность сотрудников и материально-ответственных лиц, далее — вопросы по ИТ-инфраструктуре. Заполняли ФОИВ и подведомственные КУ на этапе подготовки перехода.

### Альбомы ТФФ (типовые форматы файлов)

Оба документа построены одинаково: аннотация → регламент обмена (диаграммы загрузки/выгрузки, действия ролей) → проверки при загрузке и сообщения протокола → требования к оформлению XML и XML-схема. Титул: «Описание форматов взаимодействия централизованного ПО и ведомственных информационных систем». Версии: v1.0 (доходы/временное распоряжение) и v1.1 (реестр начислений; добавлены данные по поступлению, выбытию и возврату средств от поставщиков).

### Руководство пользователя МАД

МАД — аббревиатура из имени архива; **в самом тексте руководства она не расшифрована**. Документ описывает операции «Администратора доходов» и «Бухгалтера» с документами «Реестр начислений» и выгрузками реестра поступлений по доходам ФБ и средств во временном распоряжении. В том же архиве — инструкция обработки «Устранение дублей физлиц»: поиск дублей контрагентов по полному совпадению ФИО и дублей их договоров по номеру и дате; доступна пользователям с полномочием по учёту операций администрирования доходов.

### Письмо ФК № 07-04-05/13-9207 и настройка обмена

Письмо от 08.05.2019 адресовано территориальным органам ФК и описывает включение механизма информационного взаимодействия ИС «АСФК» и ПУиО системы «Электронный бюджет» для организаций, передавших полномочия по ведению бюджетного учёта в ФК. Сопутствующий документ «АСФК. Требования к настройке обмена с ПФХД» касается настройки проверки электронной подписи на СУФД-Логистике (конфигурационный файл `crypto.xml`). Планы финансово-хозяйственной деятельности как объект обмена — см. [ПФХД](/reporting/pfhd).

## Ограничения и особенности

- **Это не источник данных.** Не используйте страницу как «данные об исполнении ПП № 658»: показатель исполнения постановления из неё не извлекается.
- ZIP-архив Казначейства с русскими именами членов записан без UTF-8-флага: Python `zipfile` показывает CP437-кракозябры; читаемое имя даёт перекодировка CP437 → CP866 (см. [аналогичную ловушку в ZIP форм федерального бюджета](/data-sources/federal/roskazna-federal-budget-execution)).
- `prilozheniya_k_karte_kontrolya.rar` — RAR v5: штатный `unzip` не подходит, нужен `unar`/`unrar`.
- Два документа внутри архива настройки — старый бинарный формат .doc (CFB), не OOXML: `python-docx` их не читает; на macOS текст извлекается `textutil -convert txt`.
- Презентация `prezentatsiya.pdf` набрана CID-шрифтами без корректной карты ToUnicode: автоматическое извлечение русского текста невозможно без ручного маппинга.
- Ссылка на страницу из меню может меняться (пункт уже однажды мигрировал в ветку `/gis/`); сохраняйте снимок HTML и пути вложений с датой доступа.

## Примеры доступа

Скачивание файла с URL-кодированием и чтение DOCX без специализированных библиотек:

```bash
curl -k -A "Mozilla/5.0" -o karta_kontrolya.docx \
  "https://roskazna.gov.ru/uploads/migrate/roskaznagovru/documents/gis/ispolnenie-pp-rf-658/c9a/karta_kontrolya.docx"
```

```python
import re, html, subprocess, zipfile

BASE = "https://roskazna.gov.ru"
page = subprocess.run(
    ["curl", "-sk", "-A", "Mozilla/5.0", f"{BASE}/gis/ispolnenie-pp-rf-658/"],
    capture_output=True, text=True, check=True).stdout
paths = list(dict.fromkeys(html.unescape(p) for p in re.findall(r"downloadFile\('([^']+)'\)", page)))
# paths: относительные адреса всех вложений страницы

def docx_paragraphs(path):
    with zipfile.ZipFile(path) as z:
        xml = z.read("word/document.xml").decode("utf-8")
    xml = re.sub(r"</w:p>", "\n", xml)
    return [line for line in (re.sub(r"<[^>]+>", "", xml)).split("\n") if line.strip()]

print(docx_paragraphs("karta_kontrolya.docx")[:5])

def zip_member_names(path):  # русские имена в CP866
    with zipfile.ZipFile(path) as z:
        return [i.filename if i.flag_bits & 0x800
                else i.filename.encode("cp437").decode("cp866") for i in z.infolist()]

print(zip_member_names("rukovodstvo-polzovatelya-po-rabote-s-mad.zip"))
```

Пример проверен в этой среде 2026-10-02 на скачанных копиях; обход TLS-проверки в `curl -k` — исследовательский, для производственного загрузчика используйте корректное хранилище сертификатов.

- [44-ФЗ](/legal/44fz) — контрактная система, в рамках которой устроены централизованные закупки ПО.
- [Бюджетный кодекс](/legal/budget-code) — казначейские полномочия (ст. 166.1) как правовая рамка централизации учёта.
- [Отчёты Федерального казначейства](/data-sources/federal/roskazna-reports) — карта разделов портала, к которым примыкает ветка `/gis/`.
- [ГРБС](/glossary/grbs) — роль ФОИВ в бюджетном процессе, определявшая «очереди» перехода.

## Не путать с

- [Наборы данных ГИИС «Электронный бюджет»](/data-sources/federal/budget-gov-ru-datasets) — открытые датасеты той же системы, а не методическая страница.
- [Казначейство: использование выделяемых бюджетных средств](/data-sources/federal/roskazna-budget-funds-use) — созвучный пункт другого меню с фактическими показателями расходов главы 100.

## История и контекст

Страница фиксирует короткий, но важный эпизод централизации бюджетного учёта: осенью 2019 — зимой 2020 года ФОИВ «второй очереди» готовились передать Казначейству ведение учёта, отчётности и начисление выплат с 01.01.2020 (первая очередь перешла годом раньше). Казначейство провело серию ВКС (декабрь 2019 — январь 2020), собрало карты контроля ИТ-готовности организаций и опубликовало форматы обмена, по которым централизованное ПО (закупаемое по ПП № 658) стыковалось с унаследованными ведомственными ИС. После апреля 2020 страница не пополнялась и осталась памятником этого перехода; сами механизмы учёта продолжают работать в контуре [казначейского исполнения](/glossary/treasury-execution) и «Электронного бюджета».

## Частые вопросы

**В: Есть ли на странице данные об исполнении постановления № 658 — объёмы закупок ПО, охват органов?**

**О:** Нет. Страница содержит только методические материалы этапа перехода (анкеты, форматы, инструкции, презентации). Сведения о централизованных закупках ПО ищите в контуре [закупочных источников](/legal/44fz); показатели исполнения бюджета — в [формах Казначейства](/data-sources/federal/roskazna-federal-budget-execution).

**В: Зачем аналитику альбомы ТФФ, если это не датасет?**

**О:** Это единственная публичная спецификация того, как выглядел XML-обмен ведомственных ИС с «Электронным бюджетом» по реестру начислений и доходам: структура полей, кодировка WINDOWS-1251, правило именования файлов и контрольные проверки. При разборе унаследованных интеграционных выгрузок или реконструкции провениенса данных эта спецификация — первичный документ.

**В: Что такое МАД?**

**О:** Достоверной расшифровки в самих документах нет: аббревиатура фигурирует только в имени архива. Руководство под ней описывает работу с документами «Реестр начислений» и выгрузками по доходам федерального бюджета и средствам во временном распоряжении в «Электронном бюджете». Не воспроизводите расшифровку из сторонних источников без проверки.

**В: Почему страница в ветке `/gis/` и больше не обновляется?**

**О:** Волна перехода ФОИВ второй очереди завершилась к январю 2020 года; последний документ (обновление инструкции по дублям контрагентов) опубликован 16.04.2020. Страница осталась как справочная — актуальные описания «Электронного бюджета» смотрите в карточке соответствующей [информационной системы](/information-systems/federal/giis-eb).
